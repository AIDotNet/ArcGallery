## 何時使用

`ArmingSwitch` 把一個危險操作變成一套簡短的儀式。髮絲紋鋁面板上有一根鍍鉻撥桿，罩在半透明的安全護蓋下面，旁邊是一盞外圍帶圓環的指示燈。沿鉸鏈掀起護蓋，把撥桿往上扳，直到它越過中點彈到定位、指示燈閃爍著亮起，然後按住指示燈直到圓環填滿。操作開始執行，指示燈變綠，護蓋隨後自動落下，在落下途中把撥桿推回安全位置。任何時候闔上護蓋都會讓已待發的開關回到安全狀態，和真實面板一樣。

- **正式環境發布、資料遷移等不可逆操作**：絕不能因為一次誤點就開始。
- **設定中的危險區域**：一個帶保護的控制項承擔整個決定，而且有足夠的空間放下它。
- **發布時刻或產品頁面**：展示一個工具多麼認真地看待破壞性操作。

## 何時不用

- **密集清單或工具列中的快速確認**：使用 `HoldToConfirm` 或 `SlideToConfirm`。
- **需要使用者證明自己清楚要刪除什麼時**：使用要求輸入名稱的對話框。
- **可以隨意來回切換的一般設定**：使用 `Switch`。

## 用法

為操作命名，說明它影響什麼，並提供要執行的工作。`ConfirmAction` 是一個 `Func<Task<bool>>`：任務執行期間狀態為 `Running`（指示燈脈動、圓環旋轉）；`true` 表示成功，`false` 或例外表示失敗。沒有設定工作時，按住完成即直接成功。

```xml
<arc:ArmingSwitch x:Name="Purge"
                  Title="Purge the archive"
                  Description="cold-storage, 1.2 TB in 18 buckets"
                  HoldLabel="Hold to purge"
                  RunningStatusText="Purging"
                  DoneStatusText="Purged"
                  ArmedHint="Press and hold the lamp to purge the archive."
                  DoneHint="Archive purged. This cannot be undone." />
```

```csharp
Purge.HoldDuration = TimeSpan.FromMilliseconds(1800);
Purge.ConfirmAction = async () =>
{
    var result = await storage.PurgeAsync(archive.Id);
    return result.Succeeded;
};
Purge.StatusChanged += (_, e) =>
{
    if (e.NewStatus == ArmingSwitchStatus.Failed)
    {
        log.Warn(e.Error);
    }
};
```

`ArmingSwitch` 位於 Special 套件中：在 `UseArcControls()` 旁邊用 `UseArcSpecial()` 註冊。它佔用給定的寬度；面板最寬 560 px。

### 狀態

| 狀態 | 顯示內容 |
|---|---|
| `Safe` | 護蓋闔上，開關處於安全位置，指示燈熄滅，就緒燈在跳動 |
| `Open` | 護蓋翻起，可以扳動開關 |
| `Armed` | 開關扳上，指示燈亮起琥珀色並緩慢呼吸；按住指示燈會填充圓環 |
| `Running` | `ConfirmAction` 的任務執行期間，圓環旋轉、指示燈脈動 |
| `Done` | 指示燈變綠；啟用 `IsAutoSafeEnabled` 時護蓋稍後落下，把開關推回安全位置。綠燈一直亮到護蓋再次掀起 |
| `Failed` | 指示燈閃紅、面板抖動、紅色圓環排空；開關保持待發，再次按住即可重試 |

標題旁的狀態標籤把圖示和狀態文字配在一起，面板下方的一行說明下一步該做什麼；兩者都可以依狀態改名（`SafeStatusText` … `FailedStatusText`、`SafeHint` … `FailedHint`）。`StatusChanged` 回報每一次變化，操作擲回例外時附帶該例外。`CoverOpenChanged` 和 `ArmedChanged` 跟隨護蓋與開關的變化，包括落下的護蓋把開關推回的情況。圓環填滿時、操作執行之前觸發 `Confirmed`。

`OpenCover()`、`CloseCover()`、`Arm()` 和 `MakeSafe()` 可以在程式碼中驅動它。`IsLocked` 讓每個部件仍可取得焦點但都會拒絕操作：嘗試時護蓋會晃動，提示列說明開關已鎖定。

### 強調色與護蓋

按住圓環使用主題的強調色，護蓋也由它著色，並把亮度限制在一個範圍內，使其在兩種主題下都保持半透明。`AccentBrush` 改變圓環顏色，`CoverBrush` 改變護蓋及其投下的著色陰影，例如刪除操作可用安全紅。

### 內容準則

- **Title**：寫操作本身，而不是產品："Ship to production"、"Purge the archive"。
- **Description**：用一行說明它影響什麼：服務與版本、區域、資料量。
- **HoldLabel**："Hold to" 加動詞；它也是指示燈的無障礙名稱。
- **狀態文字與提示**：用於發布以外的操作時一起改名，讓狀態標籤顯示 "Purging" 的同時提示列解釋正在發生什麼。

### 最佳實務

- 它是阻力，不是授權。在 `ConfirmAction` 中到伺服器檢查權限，操作未完成時回傳 `false`。
- 回傳真實的任務，並且只在工作真正完成時才讓它結束，這樣 `Running` 才如實反映情況。
- 一次性操作保持 `IsAutoSafeEnabled` 開啟。使用者可能馬上再次執行時關閉它。

## 無障礙

- 控制項是一個以 `Title` 命名的群組。護蓋、開關和指示燈是疊放在繪製內容上的真實可聚焦元素，因此指標、觸控、鍵盤和螢幕閱讀器都作用於同樣的三個部件；面板本身對輔助技術隱藏。
- 護蓋是名為 "Lift the safety cover" 或 "Close the safety cover" 的按鈕。開關是以 `ArmLabel` 命名的切換控制項（"Arm switch"），並回報是否已待發。指示燈以 `HoldLabel` 命名。
- 每個部件的說明文字就是面板下方那一行，因此每個部件都會說明下一步做什麼。"Lift the cover first." 這類拒絕提示會取代這一行約兩秒並被朗讀。
- 禮貌型即時區域在每次狀態變化時朗讀狀態和下一步，例如 "Armed. Press and hold the lamp to ship."
- 狀態從不只依賴顏色：狀態標籤把圖示和文字配在一起，且寬度在各狀態之間保持不變。
- 鍵盤焦點會在取得焦點的部件周圍畫出 2 px 的圓角焦點環。

### 鍵盤

| 按鍵 | 操作 |
|---|---|
| `Tab` | 依序在護蓋、開關和指示燈之間移動 |
| 護蓋上的 `Enter` / `Space` | 掀起護蓋或闔上護蓋（闔上會讓已待發的開關回到安全狀態） |
| 護蓋上的 `↑` / `↓` | 掀起或闔上護蓋 |
| 開關上的 `Enter` / `Space` | 讓開關待發或回到安全狀態；護蓋闔上時撥桿會撞到蓋板，提示列要求先掀起護蓋 |
| 開關上的 `↑` / `↓` | 讓開關待發或回到安全狀態 |
| 在指示燈上按住 `Enter` 或 `Space` | 在 `HoldDuration` 內填滿圓環，然後執行操作；提早放開會排空圓環 |
| `Escape` | 讓一切回到安全狀態：結束按住、闔上護蓋、開關回到安全位置（操作執行期間忽略） |

## 動態效果

- 一個影格迴圈以彈簧驅動所有部件（240 Hz），沒有部件運動時就休眠。面板沿柔和的彈簧朝指標傾斜幾度；光源固定在房間裡，所以髮絲紋面板上的條紋會漂移，抬起的蓋板上會滑過反光，陰影會滑動並變短。
- 護蓋是鉸鏈上的半透明 3D 盒子。拖曳時蓋緣始終保持在指標下方，越過開啟的止點會有橡皮筋效果，並保留放開時的速度。它被彈簧壓向止點：約 200 ms 彈開並輕微回彈，落下時有一次短促的跳動。懸停或聚焦時抬起 5°，首次出現時會跳動一下。
- 撥桿在越過中點前一比一跟隨指標，越過後由過中點彈簧在約 65 ms 內把它甩到另一端。沒過中點就放開，它會彈回原位。
- 待發時指示燈像燈絲一樣亮起：兩次快速閃爍、一圈光暈和灑在面板上的暖光，然後緩慢呼吸。按住時鏡片被壓下，圓環帶著明亮的前端點逐漸填滿，指示燈變得更亮。
- 圓環填滿時，一圈光環從指示燈彈出，面板輕微一頓。成功時指示燈漸變為綠色，伴隨更寬的光環和一道掃過面板的反光；失敗時閃紅、面板抖動，紅色圓環排空。
- 控制項不在螢幕上時影格迴圈停止。

| 變化 | 完整 | 減少 | 關閉 |
|---|---|---|---|
| 護蓋、開關 | 彈簧、回彈、跳動 | 直接跳到新姿態 | 直接跳變 |
| 面板傾斜、漂移、就緒燈、呼吸 | 有 | 無 | 無 |
| 指示燈 | 閃爍、光暈、執行時脈動 | 淡入淡出，脈動較慢 | 常亮 |
| 按住圓環 | 稍有延遲地填充，依彈簧排空 | 填充，線性排空 | 填充，線性排空 |
| 光環、反光、抖動 | 有 | 無 | 無 |

在任何動態效果等級下按住都仍會填充圓環，因此操作始終保留這道保護。

## 響應式行為

- 面板依自身單位繪製，因此護蓋、撥桿、指示燈、螺絲和刻字從手機到桌面卡片都保持比例，面板最寬 560 px。刻字不會小於 9 px。
- 寬度達到 720 px 時，標題、狀態和提示排成一欄放在面板旁邊。低於此寬度時它們上下堆疊，卡片去掉外框，並用一條線隔開提示列；低於 420 px 時內距收緊。
- 舞台在面板上方為翻起的護蓋留出空間，因此它不會遮住標題。

## 相關元件

- `HoldToConfirm`：精簡的按住確認。
- `SlideToConfirm`：在例行操作前做出明確的水平手勢。
- `ConfirmMorph`：變成內嵌確認的破壞性按鈕。

| 元件 | 適用情境 |
|---|---|
| `ArmingSwitch` | 代價高、難以復原、值得兩步儀式且有空間放下的單一操作 |
| `HoldToConfirm` | 在小空間裡按住確認的破壞性操作 |
| `SlideToConfirm` | 觸控螢幕上例行但重要的操作 |
