## 何時使用

`SlideToConfirm` 要求在操作執行前做出一個明確的水平手勢。白色滑塊位於圓角軌道的起點，旁邊是操作說明。拖曳時，液態填色稍慢一步跟隨滑塊：滑塊領先時它會收細成一段細頸，滑塊放慢後再追上；同時軌道會在按住的滑塊周圍輕輕鼓起。沒到盡頭就放開，滑塊會彈回；越過門檻後放開，軌道會收進滑塊，任務執行期間顯示轉圈，接著箭頭變成勾號，旁邊寫出確認文字。

- **付款與轉帳**：在以手機為主的介面上，誤觸絕不能把錢轉出去。
- **解鎖或啟動某樣東西**：自助服務機或現場應用程式裡的門、班次、一次機器運轉。
- **任何不應誤觸發、但也不需要對話框說明後果的例行操作**。

## 何時不用

- **桌面介面上的破壞性操作**：使用 `HoldToConfirm`，用滑鼠按住更自然。
- **需要先閱讀後果的操作**：使用對話框。
- **容易復原的例行操作**：使用 `Button`，需要時搭配復原提示。
- **與其他按鈕並排的內嵌確認**：使用 `ConfirmMorph`。

## 用法

為滑桿設定操作說明、等待與確認狀態的文字，以及要執行的工作。工作是一個 `Func<Task>`：任務執行期間滑桿顯示轉圈與 `PendingLabel`；完成後顯示勾號與 `ConfirmedLabel`；拋出例外時，`ErrorLabel` 取代操作說明。沒有設定工作時，滑桿直接顯示勾號。

```xml
<arc:SlideToConfirm x:Name="Pay"
                    Label="Slide to pay $86"
                    PendingLabel="Paying"
                    ConfirmedLabel="Paid to Noor"
                    ErrorLabel="Not paid, slide to retry" />
```

```csharp
Pay.ConfirmAction = () => payments.SendAsync(order);
Pay.ResetAfter = TimeSpan.FromSeconds(2.6);
Pay.StateChanged += (_, e) =>
{
    if (e.NewState == SlideToConfirmState.Error)
    {
        log.Warn(e.Error);
    }
};
```

`SlideToConfirm` 位於 Special 套件中：在 `UseArcControls()` 旁邊用 `UseArcSpecial()` 註冊。它佔滿分配到的寬度（至少 200 px），高度由自身決定。

### 狀態

| 狀態 | 顯示內容 |
|---|---|
| `Idle` | 滑塊位於起點並顯示箭頭，操作說明在軌道中 |
| `Dragging` | 滑塊被指標按住，或在按住 Space / Enter 時自動滑動 |
| `Pending` | 軌道收成終點處的圓，滑塊上顯示轉圈，旁邊是 `PendingLabel` |
| `Done` | 填色的圓中顯示勾號，旁邊是 `ConfirmedLabel` |
| `Error` | 回到起點，`ErrorLabel` 以危險色取代操作說明，直到下一次滑動 |

一次滑動完成時（工作執行之前）觸發一次 `Confirmed`。`StateChanged` 回報每次狀態變化，工作失敗時附帶例外。`Confirm()` 從程式碼完成一次滑動，`Reset()` 讓已確認的滑桿回到閒置狀態；設定了 `ResetAfter` 時會自動完成這一步。

### 門檻與提示

`Threshold`（預設 0.9，範圍 0.5 到 1）是放開時滑塊至少要到達的軌道比例。越過盡頭後滑塊仍以橡皮筋方式跟隨，所以拉過頭也不會像撞上牆。滑桿閒置且無人觸碰時，`IsHintEnabled` 每隔幾秒把滑塊向右輕推一小段再收回，讓人看出它可以移動；在軌道上遠離滑塊的地方按下，會播放一個更小的輕推。

### 強調色

<Demo name="Accent" />

`AccentBrush` 改變液態填色與成功圓的顏色。不設定時它們使用主題的控制項填色，跟隨所選的強調色。液態上的文字與勾號保持主題的字形顏色，所以請選擇夠深或夠飽和的強調色來承載它們。

### 內容準則

- **Label**：操作及其對象，短到在手機上也能放在滑塊旁邊："Slide to pay $86"、"Slide to unlock door 3"。
- **PendingLabel**：一個詞說明進行中的工作："Paying"、"Unlocking"。
- **ConfirmedLabel**：結果，有幫助時寫出對象："Paid to Noor"、"Unlocked"。
- **ErrorLabel**：說明出了什麼問題，並告訴使用者再次滑動即可重試："Door offline, slide to retry"。

### 最佳實務

- 從 `ConfirmAction` 回傳真實請求的任務，這樣等待與錯誤狀態才真實可信。
- 保持較高的 `Threshold`。降低它會讓隨手一拖也算數，失去意義。
- 同一操作可以再次執行時（門、班次）使用 `ResetAfter`；已確認狀態就是流程終點時（付款收據）不要設定。

## 無障礙

- 滑桿是一個可取得焦點的元素，角色為滑桿，名稱取自 `Label`（或 `AutomationProperties.Name`）。它的值是滑塊位置，從 0 到 100；說明文字解釋用法，在等待或確認時讀出 "Paying" 或 "Paid to Noor"。
- 一個禮貌型即時區域會朗讀等待、確認與錯誤文字。
- 等待或確認期間滑桿為唯讀，忽略輸入。
- 成功從不只依賴顏色：箭頭變成勾號，旁邊寫出確認文字。失敗時錯誤文字取代操作說明。
- 指標取得焦點時不畫焦點環。鍵盤焦點會在軌道外畫一個 2 px 的膠囊形焦點環，並為軌道著色。

### 鍵盤

| 按鍵 | 操作 |
|---|---|
| `Tab` | 把焦點移到滑桿 |
| `→` `↑` / `←` `↓` | 滑塊移動十分之一的距離 |
| `Page Up` / `Page Down` | 滑塊移動四分之一的距離，並取最近的十分位 |
| `Home` | 滑塊回到起點 |
| `End` | 確認 |
| 按住 `Space` 或 `Enter` | 滑塊自動滑到盡頭並確認；提早放開則彈回 |

方向鍵與 Page 鍵本身從不確認，即使已到盡頭。

## 動態效果

- 滑塊以較硬的彈簧跟隨指標，放開時保留速度，所以快速一甩會先繼續前進片刻再彈回。在起點它會壓進邊緣、被壓扁，再輕輕彈回。
- 液態的尾端以較軟的彈簧追趕滑塊。兩者之間的細頸隨距離拉開而變細（約為間距的 15%），所以快速拖曳會拉長液體，滑塊放慢時它再追上。提早放開時，尾端會越過正在返回的滑塊並被吸收。
- 按下時滑塊膨脹約一個像素，並以欠阻尼彈簧把周圍的軌道向外推，邊緣會像薄膜一樣輕微晃動。速度會加大鼓起，並把滑塊沿拖曳方向拉成橢圓（最多 1.36 : 1）。
- 滑塊前進時，操作說明向右漂移 12 px 並淡到 30%。
- 確認：滑塊先停在終點，接著軌道在約 600 ms 內從左側收進滑塊。收到三分之一時操作說明消失，等待或確認文字隨後退的邊緣滑入，箭頭淡出為轉圈。成功時圓在約 130 ms 內變成填色，箭頭的三個點在約 250 ms 內滑成勾號。重設時以相反順序播放。
- 所有這些由一個影格迴圈驅動，一切靜止後立即休眠；滑桿不在畫面上時停止。

| 變化 | 完整 | 減弱 | 關閉 |
|---|---|---|---|
| 拖曳 | 彈簧跟隨、液體滯後與細頸、鼓起、拉伸 | 滑塊精確跟隨；無液體滯後、鼓起或拉伸 | 同減弱 |
| 放開、按鍵 | 彈簧 | 立即 | 立即 |
| 確認、成功、重設、錯誤 | 收縮、淡變、形變 | 立即（等待時轉圈靜止） | 立即 |
| 閒置輕推 | 每隔幾秒 | 無 | 無 |
| 懸停著色 | 150 ms | 150 ms | 立即 |

按住 Space 或 Enter 時，在完整與減弱動態效果下滑塊都會自動滑動；動態效果關閉時則立即確認。自動重設後滑塊總會回到起點。

## 響應式行為

- 寬度小於 360 px 時軌道高 56 px，從 360 px 起高 64 px。滑塊保持 5 px 內距，高軌道上操作說明從 13 px 增大到 15 px。
- 滑桿佔滿分配到的寬度，至少 200 px。請讓操作說明短到在你支援的最窄寬度下也能放在滑塊旁邊。
- 觸控時只有水平拖曳會移動滑塊；垂直滑動仍會捲動頁面。

## 相關元件

- `HoldToConfirm`：透過按住來確認破壞性操作。
- `ConfirmMorph`：按鈕變成內嵌確認。
- `ElasticSlider`：越過兩端會拉伸的數值滑桿。

| 元件 | 何時選擇 |
|---|---|
| `SlideToConfirm` | 在例行但重要的操作之前要求一個明確的水平手勢 |
| `HoldToConfirm` | 桌面上的破壞性操作，透過按住確認 |
| `ConfirmMorph` | 與其他操作並排的內嵌確認步驟 |
