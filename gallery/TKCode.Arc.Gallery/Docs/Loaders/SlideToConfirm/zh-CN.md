## 何时使用

`SlideToConfirm` 要求在操作执行前做出一个明确的水平手势。白色滑块位于圆角轨道的起点，旁边是操作说明。拖动时，液态填充稍慢一步跟随滑块：滑块领先时它会收细成一段细颈，滑块放慢后再追上；同时轨道会在按住的滑块周围轻轻鼓起。没到尽头就松手，滑块会弹回；越过阈值后松手，轨道会收进滑块，任务运行期间显示转圈，随后箭头变成对勾，旁边写出确认文字。

- **支付与转账**：在以手机为主的界面上，误触绝不能把钱转出去。
- **解锁或启动某样东西**：自助终端或现场应用里的门、班次、一次机器运行。
- **任何不应误触发、但也不需要对话框解释后果的常规操作**。

## 何时不用

- **桌面界面上的破坏性操作**：使用 `HoldToConfirm`，用鼠标按住更自然。
- **需要先阅读后果的操作**：使用对话框。
- **容易撤销的常规操作**：使用 `Button`，需要时配合撤销提示。
- **与其他按钮并排的内联确认**：使用 `ConfirmMorph`。

## 用法

为滑块设置操作说明、等待与确认状态的文字，以及要执行的工作。工作是一个 `Func<Task>`：任务运行期间滑块显示转圈和 `PendingLabel`；完成后显示对勾和 `ConfirmedLabel`；抛出异常时，`ErrorLabel` 取代操作说明。没有设置工作时，滑块直接显示对勾。

```xml
<arc:SlideToConfirm x:Name="Pay"
                    Label="Slide to pay $86"
                    PendingLabel="Paying"
                    ConfirmedLabel="Paid to Noor"
                    ErrorLabel="Not paid, slide to retry" />
```

```csharp
Pay.ConfirmAction = () => payments.SendAsync(order);
Pay.ResetAfter = TimeSpan.FromSeconds(2.6);
Pay.StateChanged += (_, e) =>
{
    if (e.NewState == SlideToConfirmState.Error)
    {
        log.Warn(e.Error);
    }
};
```

`SlideToConfirm` 位于 Special 包中：在 `UseArcControls()` 旁边用 `UseArcSpecial()` 注册。它占满分配到的宽度（至少 200 px），高度由自身决定。

### 状态

| 状态 | 显示内容 |
|---|---|
| `Idle` | 滑块位于起点并显示箭头，操作说明在轨道中 |
| `Dragging` | 滑块被指针按住，或在按住 Space / Enter 时自动滑动 |
| `Pending` | 轨道收成终点处的圆，滑块上显示转圈，旁边是 `PendingLabel` |
| `Done` | 填充色的圆中显示对勾，旁边是 `ConfirmedLabel` |
| `Error` | 回到起点，`ErrorLabel` 以危险色取代操作说明，直到下一次滑动 |

一次滑动完成时（工作运行之前）触发一次 `Confirmed`。`StateChanged` 报告每次状态变化，工作失败时附带异常。`Confirm()` 从代码完成一次滑动，`Reset()` 让已确认的滑块回到空闲状态；设置了 `ResetAfter` 时会自动完成这一步。

### 阈值与提示

`Threshold`（默认 0.9，范围 0.5 到 1）是松手时滑块至少要到达的轨道比例。越过尽头后滑块仍以橡皮筋方式跟随，所以拉过头也不会像撞上墙。滑块空闲且无人触碰时，`IsHintEnabled` 每隔几秒把滑块向右轻推一小段再收回，让人看出它可以移动；在轨道上远离滑块的地方按下，会播放一个更小的轻推。

### 强调色

<Demo name="Accent" />

`AccentBrush` 改变液态填充和成功圆的颜色。不设置时它们使用主题的控件填充色，跟随所选的强调色。液态上的文字和对勾保持主题的字形颜色，所以请选择足够深或足够饱和的强调色来承载它们。

### 内容准则

- **Label**：操作及其对象，短到在手机上也能放在滑块旁边："Slide to pay $86"、"Slide to unlock door 3"。
- **PendingLabel**：一个词说明进行中的工作："Paying"、"Unlocking"。
- **ConfirmedLabel**：结果，有帮助时写出对象："Paid to Noor"、"Unlocked"。
- **ErrorLabel**：说明出了什么问题，并告诉用户再次滑动即可重试："Door offline, slide to retry"。

### 最佳实践

- 从 `ConfirmAction` 返回真实请求的任务，这样等待与错误状态才真实可信。
- 保持较高的 `Threshold`。降低它会让随手的一拖也算数，失去意义。
- 同一操作可以再次执行时（门、班次）使用 `ResetAfter`；已确认状态就是流程终点时（支付回执）不要设置。

## 无障碍

- 滑块是一个可聚焦的元素，角色为滑块，名称取自 `Label`（或 `AutomationProperties.Name`）。它的值是滑块位置，从 0 到 100；帮助文字说明用法，在等待或确认时读出 "Paying" 或 "Paid to Noor"。
- 一个礼貌型实时区域会朗读等待、确认和错误文字。
- 等待或确认期间滑块为只读，忽略输入。
- 成功从不只依赖颜色：箭头变成对勾，旁边写出确认文字。失败时错误文字取代操作说明。
- 指针获得焦点时不画焦点环。键盘焦点会在轨道外画一个 2 px 的胶囊形焦点环，并给轨道着色。

### 键盘

| 按键 | 操作 |
|---|---|
| `Tab` | 把焦点移到滑块 |
| `→` `↑` / `←` `↓` | 滑块移动十分之一的距离 |
| `Page Up` / `Page Down` | 滑块移动四分之一的距离，并取最近的十分位 |
| `Home` | 滑块回到起点 |
| `End` | 确认 |
| 按住 `Space` 或 `Enter` | 滑块自动滑到尽头并确认；提前松开则弹回 |

方向键和 Page 键本身从不确认，即使已到尽头。

## 动效

- 滑块以较硬的弹簧跟随指针，松手时保留速度，所以快速一甩会先继续前进片刻再弹回。在起点它会压进边缘、被压扁，再轻轻弹回。
- 液态的尾部以较软的弹簧追赶滑块。两者之间的细颈随距离拉开而变细（约为间距的 15%），所以快速拖动会拉长液体，滑块放慢时它再追上。提前松手时，尾部会越过正在返回的滑块并被吸收。
- 按下时滑块膨胀约一个像素，并以欠阻尼弹簧把周围的轨道向外推，边缘会像薄膜一样轻微晃动。速度会加大鼓起，并把滑块沿拖动方向拉成椭圆（最多 1.36 : 1）。
- 滑块前进时，操作说明向右漂移 12 px 并淡到 30%。
- 确认：滑块先停在终点，然后轨道在约 600 ms 内从左侧收进滑块。收到三分之一时操作说明消失，等待或确认文字随后退的边缘滑入，箭头淡出为转圈。成功时圆在约 130 ms 内变成填充色，箭头的三个点在约 250 ms 内滑成对勾。重置时按相反顺序播放。
- 所有这些由一个帧循环驱动，一切静止后立即休眠；滑块不在屏幕上时停止。

| 变化 | 完整 | 减弱 | 关闭 |
|---|---|---|---|
| 拖动 | 弹簧跟随、液体滞后与细颈、鼓起、拉伸 | 滑块精确跟随；无液体滞后、鼓起或拉伸 | 同减弱 |
| 松手、按键 | 弹簧 | 立即 | 立即 |
| 确认、成功、重置、错误 | 收缩、淡变、形变 | 立即（等待时转圈静止） | 立即 |
| 空闲轻推 | 每隔几秒 | 无 | 无 |
| 悬停着色 | 150 ms | 150 ms | 立即 |

按住 Space 或 Enter 时，在完整和减弱动效下滑块都会自动滑动；动效关闭时则立即确认。自动重置后滑块总会回到起点。

## 响应式行为

- 宽度小于 360 px 时轨道高 56 px，从 360 px 起高 64 px。滑块保持 5 px 内边距，高轨道上操作说明从 13 px 增大到 15 px。
- 滑块占满分配到的宽度，至少 200 px。请让操作说明短到在你支持的最窄宽度下也能放在滑块旁边。
- 触摸时只有水平拖动会移动滑块；垂直滑动仍会滚动页面。
