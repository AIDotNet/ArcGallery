## 何時使用

`CodeMagicMove` 展示一段程式碼如何從一個版本變成下一個版本。每一步是程式碼的一個版本，帶一個簡短的標題。演練前進時，保留下來的詞滑到新的行和欄，去掉的詞淡出並向上浮起，新程式碼則在強調色游標後一個字元一個字元地輸入，同時程式碼區塊按新的行數變高或變矮。這一步引入的行保留一條淺色底帶和一條強調色豎線，頁首寫出這一步增加和刪除的行數。步驟圓點、方向鍵和橫向拖曳都能在步驟之間移動，預設情況下演練會自己播放。

- **文件頁和著陸頁的段落**：一步一步搭起一段程式碼來講解一個 API。
- **更新日誌和升級指南**：準確展示一個呼叫或一份設定在兩個版本之間改了什麼。

## 何時不用

- **人們要複製的單段程式碼**：用 `CodeBlock`。
- **大檔案或程式碼審查**：用真正的差異檢視。這個元件適合能放在一屏裡的短程式碼。

## 用法

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             xmlns:arc="https://github.com/AIDotNet/TKCode.Arc">
    <arc:CodeMagicMove x:Name="Walkthrough" FileName="client.ts" Language="ts" Label="Quick start" />
</UserControl>
```

```csharp
Walkthrough.Steps.Add(new CodeMagicMoveStep("Open a connection", "const db = connect();"));
Walkthrough.Steps.Add(new CodeMagicMoveStep("Pass your settings", """
    const db = connect({
      url: process.env.DATABASE_URL,
    });
    """, "Read the address from the environment."));
```

`CodeMagicMove` 是 Special 套件裡的控制項。在 `UseArcControls()` 旁邊用 `UseArcSpecial()` 註冊這個套件。它的內容是 `Steps`，一個 `CodeMagicMoveStep` 清單：該版本的 `Code`、一個 `Title`、標題下可選的 `Description`，以及可選的 `FileName`（這一步用它代替頁首的 `FileName`）。程式碼最好用 C# 原始字串常值來寫；定位字元會變成兩個空格，所有行共有的縮排會被去掉。

裝了醒目提示套件（`UseArcHighlighting()`，設定 `Language`，預設 "tsx"）時，詞的顏色與 `CodeBlock` 一致；沒裝時程式碼是前景色的純文字。

### 步驟與值

`Value` 是目前顯示的步驟序號，可雙向繫結；設定它就會移動到那一步。移動開始朝向另一步時，或拖曳確認到另一步時，`ValueChanged` 回報新舊序號。`Next()`、`Previous()` 和 `GoTo(index)` 用於在程式碼中移動。繫結 `Value` 可以讓演練與旁邊的說明文字保持同步，比如隨著程式碼移動而醒目提示的步驟清單。

### 自動播放

開啟 `AutoPlay`（true）時，演練在每一步停留 `Interval`（3.2 秒），期間目前圓點逐漸填滿，然後前進到下一步，從最後一步循環回第一步。滑鼠懸停在上面時它會暫停計時；一旦有人切換步驟、拖曳或按下暫停，它就不再自動播放：`IsPaused` 變為 true。播放按鈕會清除它並立即前進。`IsPlaying` 表示自動播放是否在執行。`Speed` 讓每次移動的節奏成倍變化；為 1 時一次典型的移動大約一秒，要輸入的內容多或詞要跨越整個檔案時會稍長一些。

### 最佳實務

**建議**

- 每一步都是一個小而有意義的改動，配一個簡短的標題，並在說明裡講清原因。
- 把長呼叫換行：超過約 50 個字元的行會讓程式碼在手機上縮小。
- 給演練設定 `Label`；程式碼區會連同步驟位置一起朗讀它。

**避免**

- 一步把所有內容都重寫：沒有東西可以滑動，移動就變成了重新輸入。
- 把它當作複製程式碼的唯一來源；最終版本旁邊再放一個 `CodeBlock`。

### 常見問題

**版本之間的詞是怎麼對應的？** 先沿著詞的最長公共序列對應；兩邊剩下的同文字詞再按距離配對，所以整行移動的程式碼會滑過去，而不是重新輸入。

**哪些行會有底帶？** 與上一步相比，含有至少一個新詞的行。頁首的計數是忽略空行的行級差異。

## 無障礙

- 程式碼區是一個可聚焦的群組，名稱為「Label, step n of total」，並由鍵盤提示描述。目前步驟的完整程式碼以純文字形式存在於樹中，所以輔助技術讀到的是真實的程式碼，而不是繪製出來的圖層。
- 上一步、下一步、每個步驟圓點（「Step n: title」）和播放或暫停都是真正的按鈕，各有具體的名稱。
- 一個禮貌型即時區域會播報人們選擇的每一步：它的標題，以及增加和刪除了多少行。自動播放不會播報，暫停按鈕可以停止它。
- 變化從不只靠顏色表達：頁首寫出行數，說明文字點出步驟名，改動的行除了底色還有一條豎線。
- 鍵盤聚焦時沿程式碼區畫出焦點環；指標聚焦時不畫。

### 鍵盤互動

| 按鍵 | 操作 |
|---|---|
| `Tab` | 聚焦程式碼區，然後是各個按鈕和圓點 |
| `Left` / `Up` | 上一步 |
| `Right` / `Down` | 下一步 |
| `Home` / `End` | 第一步 / 最後一步 |

## 動效

- 刪除的詞在 262 ms 內按標準曲線淡出並上浮 0.28 行。
- 保留的詞按緩入緩出曲線滑動 720 ms（移動得遠時更久：600 ms 加上每跨越一行 35 ms）；有詞被刪除時從第 100 ms 開始，越往下的行晚 12 ms。高度和行號按同一條曲線跟隨行數變化。
- 滑動進行到 60% 時開始輸入新程式碼，大約每秒 28 個字元（改動很長時輸入得更快，所以輸入不會超過 1.5 秒）；標點和空白後的第一個字元稍慢一些。每個詞在 50 ms 內淡入；最後一個字元之後游標等待 50 ms，再用 300 ms 淡出。
- 新一步的底帶在輸入到達時用 220 ms 淡入；舊底帶與刪除的詞一起淡出。
- 每次移動都是其進度的函數：拖曳可以拖著它走，超過三分之一（或快速甩動）就確認，否則倒回；移動中途退回上一步會反向播放，移動中途選新的一步會從每個詞目前的位置出發。在兩端，程式碼會像橡皮筋一樣被拉開，再以臨界阻尼彈簧回到原位。
- 一個影格迴圈寫入各個詞的位置，只在有東西移動、自動播放計時或程式碼回彈時執行；離開螢幕時停止。

| 變化 | 完整 | 減弱 | 關閉 |
|---|---|---|---|
| 步驟 | 滑動、上浮與輸入 | 立即切換 | 立即切換 |
| 自動播放 | 執行 | 關閉 | 關閉 |
| 底帶與計數 | 淡入 | 立即顯示 | 立即顯示 |

## 響應式行為

- 程式碼字級會讓最寬的一步適應給定的寬度，從 13 px 縮到 10.5 px，所以行不會換行，詞也不會擠在一起。
- 寬度小於 520 px 時，說明文字單獨佔一行，步驟控制項鋪滿整個寬度，圓點高 44 px。
- 只能橫向拖曳，所以觸控螢幕上的縱向捲動照常可用。

## 相關元件

- `CodeBlock` 展示一段可以複製的程式碼。
- `TypewriterTerminal` 逐行播放一段終端機工作階段。

| 元件 | 何時選擇 |
|---|---|
| `CodeMagicMove` | 重點是版本之間的變化 |
| `CodeBlock` | 人們需要閱讀或複製一段程式碼 |
| `TypewriterTerminal` | 要播放一段命令列工作階段 |
