## 何时使用

`CodeMagicMove` 展示一段代码如何从一个版本变成下一个版本。每一步是代码的一个版本，带一个简短的标题。演练前进时，保留下来的词滑到新的行和列，去掉的词淡出并向上浮起，新代码则在强调色光标后一个字符一个字符地输入，同时代码块按新的行数变高或变矮。这一步引入的行保留一条浅色底带和一条强调色竖线，页头写出这一步增加和删除的行数。步骤圆点、方向键和横向拖动都能在步骤之间移动，默认情况下演练会自己播放。

- **文档页和落地页的段落**：一步一步搭起一段代码来讲解一个 API。
- **更新日志和升级指南**：准确展示一个调用或一份配置在两个版本之间改了什么。

## 何时不用

- **人们要复制的单段代码**：用 `CodeBlock`。
- **大文件或代码评审**：用真正的差异视图。这个组件适合能放在一屏里的短代码。

## 用法

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             xmlns:arc="https://github.com/AIDotNet/TKCode.Arc">
    <arc:CodeMagicMove x:Name="Walkthrough" FileName="client.ts" Language="ts" Label="Quick start" />
</UserControl>
```

```csharp
Walkthrough.Steps.Add(new CodeMagicMoveStep("Open a connection", "const db = connect();"));
Walkthrough.Steps.Add(new CodeMagicMoveStep("Pass your settings", """
    const db = connect({
      url: process.env.DATABASE_URL,
    });
    """, "Read the address from the environment."));
```

`CodeMagicMove` 是 Special 包里的控件。在 `UseArcControls()` 旁边用 `UseArcSpecial()` 注册这个包。它的内容是 `Steps`，一个 `CodeMagicMoveStep` 列表：该版本的 `Code`、一个 `Title`、标题下可选的 `Description`，以及可选的 `FileName`（这一步用它代替页头的 `FileName`）。代码最好用 C# 原始字符串字面量来写；制表符会变成两个空格，所有行共有的缩进会被去掉。

装了高亮包（`UseArcHighlighting()`，设置 `Language`，默认 "tsx"）时，词的颜色与 `CodeBlock` 一致；没装时代码是前景色的纯文本。

### 步骤与值

`Value` 是当前显示的步骤序号，可双向绑定；设置它就会移动到那一步。移动开始朝向另一步时，或拖动确认到另一步时，`ValueChanged` 报告新旧序号。`Next()`、`Previous()` 和 `GoTo(index)` 用于在代码中移动。绑定 `Value` 可以让演练与旁边的说明文字保持同步，比如随着代码移动而高亮的步骤列表。

### 自动播放

开启 `AutoPlay`（true）时，演练在每一步停留 `Interval`（3.2 秒），期间当前圆点逐渐填满，然后前进到下一步，从最后一步循环回第一步。鼠标悬停在上面时它会暂停计时；一旦有人切换步骤、拖动或按下暂停，它就不再自动播放：`IsPaused` 变为 true。播放按钮会清除它并立即前进。`IsPlaying` 表示自动播放是否在运行。`Speed` 让每次移动的节奏成倍变化；为 1 时一次典型的移动大约一秒，要输入的内容多或词要跨越整个文件时会稍长一些。

### 最佳实践

**建议**

- 每一步都是一个小而有意义的改动，配一个简短的标题，并在说明里讲清原因。
- 把长调用换行：超过约 50 个字符的行会让代码在手机上缩小。
- 给演练设置 `Label`；代码区会连同步骤位置一起朗读它。

**避免**

- 一步把所有内容都重写：没有东西可以滑动，移动就变成了重新输入。
- 把它当作复制代码的唯一来源；最终版本旁边再放一个 `CodeBlock`。

### 常见问题

**版本之间的词是怎么对应的？** 先沿着词的最长公共序列对应；两边剩下的同文本词再按距离配对，所以整行移动的代码会滑过去，而不是重新输入。

**哪些行会有底带？** 与上一步相比，含有至少一个新词的行。页头的计数是忽略空行的行级差异。

## 无障碍

- 代码区是一个可聚焦的组，名称为"Label, step n of total"，并由键盘提示描述。当前步骤的完整代码以纯文本形式存在于树中，所以辅助技术读到的是真实的代码，而不是绘制出来的图层。
- 上一步、下一步、每个步骤圆点（"Step n: title"）和播放或暂停都是真正的按钮，各有具体的名称。
- 一个礼貌型实时区域会播报人们选择的每一步：它的标题，以及增加和删除了多少行。自动播放不会播报，暂停按钮可以停止它。
- 变化从不只靠颜色表达：页头写出行数，说明文字点出步骤名，改动的行除了底色还有一条竖线。
- 键盘聚焦时沿代码区画出焦点环；指针聚焦时不画。

### 键盘交互

| 按键 | 操作 |
|---|---|
| `Tab` | 聚焦代码区，然后是各个按钮和圆点 |
| `Left` / `Up` | 上一步 |
| `Right` / `Down` | 下一步 |
| `Home` / `End` | 第一步 / 最后一步 |

## 动效

- 删除的词在 262 ms 内按标准曲线淡出并上浮 0.28 行。
- 保留的词按缓入缓出曲线滑动 720 ms（移动得远时更久：600 ms 加上每跨越一行 35 ms）；有词被删除时从第 100 ms 开始，越往下的行晚 12 ms。高度和行号按同一条曲线跟随行数变化。
- 滑动进行到 60% 时开始输入新代码，大约每秒 28 个字符（改动很长时输入得更快，所以输入不会超过 1.5 秒）；标点和空白后的第一个字符稍慢一些。每个词在 50 ms 内淡入；最后一个字符之后光标等待 50 ms，再用 300 ms 淡出。
- 新一步的底带在输入到达时用 220 ms 淡入；旧底带与删除的词一起淡出。
- 每次移动都是其进度的函数：拖动可以拖着它走，超过三分之一（或快速甩动）就确认，否则倒回；移动中途退回上一步会反向播放，移动中途选新的一步会从每个词当前的位置出发。在两端，代码会像橡皮筋一样被拉开，再以临界阻尼弹簧回到原位。
- 一个帧循环写入各个词的位置，只在有东西移动、自动播放计时或代码回弹时运行；离开屏幕时停止。

| 变化 | 完整 | 减弱 | 关闭 |
|---|---|---|---|
| 步骤 | 滑动、上浮与输入 | 立即切换 | 立即切换 |
| 自动播放 | 运行 | 关闭 | 关闭 |
| 底带与计数 | 淡入 | 立即显示 | 立即显示 |

## 响应式行为

- 代码字号会让最宽的一步适应给定的宽度，从 13 px 缩到 10.5 px，所以行不会换行，词也不会挤在一起。
- 宽度小于 520 px 时，说明文字单独占一行，步骤控件铺满整个宽度，圆点高 44 px。
- 只能横向拖动，所以触屏上的纵向滚动照常可用。

## 相关组件

- `TypewriterTerminal` 逐行播放一段终端会话。

| `CodeMagicMove` | 重点是版本之间的变化 |
